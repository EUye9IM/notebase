# 快速笔记 · 交互设计（v1）

> 核心命题：把「记录一条」的操作成本压到最低。本文档只定交互逻辑，
> 不涉及视觉样式；存储格式（JSON / SQLite）对 UI 层不可见。

## 1. 设计原则

1. **录入优先**：打开应用即处于可录入状态。一切为「更快记下一条」让路。
2. **零确认**：录入/保存路径上不允许出现确认弹窗。只有破坏性操作（删除）才确认。
3. **一条一档**：一段文字、一张照片、一段录音各是一条独立记录，不混合、不加标题、不加说明文字。
4. **追加式**：时间流以追加为主。编辑历史条目是低频操作，允许但不上 shortcut。
5. **操作步数可验收**：见 §11，实现后逐条核对。

## 2. 概念模型

两个实体，一个方向（笔记本 → 条目）：

```ts
Notebook {
  id: string
  name: string
  createdAt: number
}

Entry {
  id: string
  notebookId: string
  type: 'text' | 'photo' | 'audio'
  text?: string        // type === 'text' 时的正文（可含换行）
  file?: string        // type === 'photo' | 'audio' 时的媒体文件相对路径
  duration?: number    // type === 'audio' 时长（秒）
  transcript?: string  // type === 'audio' 转写全文（录音的完整文字面）
  summary?: string     // type === 'photo' | 'audio' 摘要：短文字，时间线展示面（见 §8）
  createdAt: number
}
```

不变式：

- 永远存在名为 `default` 的默认笔记本，不可删除、不可重命名（它是删除其他笔记本时条目的去处，也是首次启动的当前笔记本）。
- 一条条目恰好属于一个笔记本。跨笔记本移动后置（见 §12）。
- 条目无标题。文本条目的首行在列表里充当视觉锚点。
- 媒体条目有两层文字（均可编辑，规则见 §8）：**转写**（仅录音，完整文字面，等价于文本条目的正文）与**摘要**（照片 = 图片描述；录音 = 转写的压缩，时间线展示面）。
- 可搜索文本（§7）：文本条目 = 正文；照片 = 摘要；录音 = 转写 + 摘要。

存储映射（当前 JSON 方案，UI 不感知）：

```
<app-data>/notebooks.json        # 笔记本索引
<app-data>/nb_<id>.json          # 每笔记本一个条目数组
<app-data>/media/<entry-id>.<ext> # 媒体文件，文件名即条目 id
```

## 3. 应用壳（信息架构）

旧壳（笔记/搜索/设置三 Tab）废弃。新壳只有两层：**笔记本选择 + 当前笔记本的时间流**。

### 窄屏（< 720）

```
┌─────────────────────────────┐
│ ▾ default           🔍  ⚙   │ ← 顶栏：笔记本名（点击=切换）、搜索、设置
├─────────────────────────────┤
│         ── 今天 ──          │
│  买了猫粮，10kg              │ ← 文本条目
│  18:42                      │
│                             │
│  ▶ 0:42  ▁▂▃▅▂▁▃            │ ← 录音条目
│  跟师傅确认了瓷砖型号         │ ← 摘要（可编辑，见 §8）
│  15:07                      │
│                             │
│  ┌─────────────┐            │
│  │  (缩略图)    │            │ ← 照片条目
│  └─────────────┘ 09:31      │
│         ── 昨天 ──          │
│  …                          │
├─────────────────────────────┤
│ 📷   🎤   [ 记点什么… ]  ➤  │ ← 输入栏（常驻）
└─────────────────────────────┘
```

自上而下三个区域：

| 区域 | 内容 | 交互 |
|---|---|---|
| 顶栏 | 当前笔记本名（▾）· 🔍 · ⚙ | 点笔记本名 → 底部弹出笔记本列表（§6）；🔍 进入搜索模式（§7）；⚙ 设置 |
| 时间流 | 当前笔记本全部条目：时间升序、按天分组（组头「今天 / 昨天 / M月d日」），最新在底部 | 滚动浏览；条目点按 / 长按见 §8 |
| 输入栏 | 📷 · 🎤 · 文本框 · ➤（常驻底部） | 三种录入入口，见 §5 |

### 宽屏（≥ 720）

```
┌────────────┬─────────────────────────────────┐
│ ▣ default  │  default                🔍      │ ← 流头部：笔记本名 + 搜索入口
│   工作     ├─────────────────────────────────┤
│   灵感     │         ── 今天 ──             │
│   阅读     │  买了猫粮，10kg       18:42     │
│            │  ▶ 0:42 ▁▂▃▅▂▁▃     15:07      │
│            │  ┌────────┐                    │
│            │  │(缩略图) │        09:31       │
│            │  └────────┘                    │
│ ＋ 新建    │         ── 昨天 ──             │
│────────────│  …                             │
│        ⚙   │ 📷  🎤  [ 记点什么… ]     ➤    │
└────────────┴─────────────────────────────────┘
   侧栏：笔记本即选择器（点即切换），无弹层
```

左右分栏：

| 区域 | 内容 | 交互 |
|---|---|---|
| 侧栏（左） | 笔记本列表（当前项高亮）· 底部「＋ 新建」· ⚙ | 点即切换；侧栏本身就是选择器，不需要弹层 |
| 流头部 | 当前笔记本名 · 🔍 | 🔍 进入搜索模式（§7） |
| 时间流 | 同窄屏；列宽上限 ~720，居中 | 同窄屏 |
| 输入栏 | 同窄屏，固定在流列底部 | 同窄屏 |

差异只在「笔记本怎么选」：窄屏用底部弹层，宽屏侧栏即选择器。时间流与输入栏在两端完全一致。

## 4. 主界面：时间流

- **顺序**：时间升序，最新在最底部（贴近输入栏，录完即所见）。打开应用、发送新条目、切换笔记本时自动滚动到底部。
- 向上翻阅超过一屏时，右下角浮现「↓ 回到最新」小按钮。
- **分组**：按天分组，组头显示 `今天` / `昨天` / `M月d日`（跨年带年份）。
- **条目渲染**：
  - text：正文原样（保留换行），下方小字时间；
  - photo：等比缩略图（宽 ≈ 列宽 60%），角标时间；
  - audio：一行内 `[▶] 时长 波形条`，播放中显示进度；
  - photo / audio：有摘要时，摘要按文本条目同款样式渲染在媒体下方（次要色），空摘要不占位；
  - audio：转写全文不进时间流（可能很长）；无摘要但有转写时，摘要位兜底显示转写首行（截断）。
- 条目本身无卡片边框，靠留白分隔；整行是点击目标。

## 5. 输入栏与三种录入流程

输入栏常驻底部：`📷 | 🎤 | [文本框] | ➤`。三个入口，各自的状态机如下。

### 5.1 文本

```
状态: idle ──(输入非空)──▶ canSend ──(➤ / Enter)──▶ 保存并清空 → idle
```

- 文本框为空时 ➤ 置灰。
- **键盘行为**：窄屏 Enter = 换行（发送靠 ➤）；宽屏 Enter = 发送，Shift+Enter = 换行。
- **焦点**：窄屏不自动弹键盘（打开是为了「看」的场景占一半，弹键盘会挡内容）；宽屏自动聚焦。
- 保存即追加到当前笔记本底部，动画一次轻滚动定位。

### 5.2 录音

```
状态: idle ──(点 🎤)──▶ recording ──(点 ✓)──▶ 保存 → idle
                                   └─(点 ✗)──▶ 丢弃 → idle
```

- 点 🎤 后输入栏整体替换为录音条，即时开始录音，无「准备好了吗」过渡：

```
┌──────────────────────────────┐
│  ✗     ● 00:12  ▂▃▅▂▃▅▂    ✓  │
└──────────────────────────────┘
  丢弃    实时时长·电平    停止并保存
```

- 电平动画可以是假波形（不真实采集）。
- **✓ 停止即保存**：不进试听/重录/命名页面。
- **✗ 立即丢弃**：不确认（误触的代价是重录一次，比确认弹窗便宜）。
- 守卫：时长 < 1s 视为误触，丢弃并 toast「太短了」。
- 播放：列表内联播放，点 ▶ 切换播放/暂停。
- 保存后（Phase 3）自动进入「转写 → 摘要」流水线，异步生成，不阻塞下一条录入（见 §8 生命周期）。

### 5.3 拍照

```
状态: closed ──(点 📷)──▶ viewfinder ──(快门)──▶ 保存并关闭 → 流内立即可见
                                     └─(返回 ✗)──▶ closed（什么都不存）
viewfinder ──(相册按钮)──▶ 系统选图 ──(选中)──▶ 保存并关闭
```

- 应用内取景器全屏（暂用系统相机亦可，实现期决定，交互不变）。
- **快门后无预览/确认步骤**，直接保存返回时间流，新条目缩略图短暂高亮作为反馈。
- 取景器角落放一个小的「相册」入口（系统选图器），满足导入已有图片的场景，不占用主路径的步数。
- 一次一张（一图一条）。多选后置。

### 5.4 步数小结（当前笔记本内）

| 动作 | 操作 |
|---|---|
| 记一段文字 | 点文本框 → 打字 → ➤ |
| 录一段音 | 🎤 → 说话 → ✓ |
| 拍一张照 | 📷 → 快门 |

## 6. 笔记本管理

### 切换（2 步）

- 窄屏：点顶栏笔记本名 → 底部弹出笔记本列表（当前项高亮）→ 点目标即切换并关闭。
- 宽屏：侧栏即列表，点即切换。
- 列表底部固定一行「＋ 新建笔记本」。

### 新建（3 步 + 输入）

- 点「＋ 新建笔记本」→ 单字段对话框（名称，非空校验）→ 「创建」→ 创建成功并**切换为当前笔记本**。

### 重命名 / 删除

- 窄屏：列表项长按（宽屏：右键）→ 菜单「重命名 / 删除」。
- 重命名：同新建对话框，预填旧名。
- 删除：
  - `default` 不提供删除；
  - 空笔记本：确认一次「删除笔记本 X？」→ 删除；
  - 非空笔记本：确认文案说明「其中 N 条记录将移入 default」→ 确认后条目并入 default，笔记本删除。
- 删除的是笔记本，条目永不陪葬。

## 7. 搜索（当前笔记本内）

范围锁定：只搜索**当前笔记本**的条目，不跨笔记本（全局搜索后置，见 §12）。

### 入口与形态

- 窄屏：顶栏 🔍；宽屏：流头部 🔍。
- 点按后顶栏原地切换为搜索模式：← 返回 · 输入框（自动聚焦）· ✗ 清空。
- 不新开页面：下方时间流区域原地变为结果列表，退出搜索恢复原流与滚动位置。

### 状态机

```
idle ──(🔍)──▶ search ──(输入)──▶ 实时过滤
search ──(← / Esc)──▶ idle
search ──(✗)──▶ 清空输入，留在 search
```

### 结果列表

- query 为空：提示「输入关键词，仅搜索当前笔记本」。
- 输入即过滤，**按时间倒序（最新在前）**，与时间流的升序相反——流是「写」的视角（贴着输入栏），搜索是「读」的视角（最新优先）。
- 头部显示「N 条结果」。
- 结果渲染与时间流条目一致（§4），命中关键词加粗/高亮（实现可选）。
- 点结果 → 打开条目详情（§8），返回后保留查询词与结果列表。

### 命中规则

- 文本条目：正文包含关键词，忽略大小写。
- 照片：摘要包含关键词即命中；无摘要不命中。
- 录音：转写或摘要任一包含关键词即命中——转写是主要命中面（全文都在那）。
- 搜索机制**现在即终态**：Phase 3 的 AI 只是转写/摘要的生产者（自动生成），搜索规则本身不再随 AI 变化。

### 无结果

「“关键词”没有匹配」居中提示，附「清空」按钮。

## 8. 条目的查看 / 编辑 / 删除

| 类型 | 点按 | 长按 / 右键菜单 |
|---|---|---|
| text | 弹出编辑底 sheet：textarea + 「保存 / 删除」 | 复制、编辑、删除 |
| photo | 全屏查看器（点空白或返回关闭） | 编辑摘要、删除 |
| audio | 列表内联播放/暂停 | 编辑转写、编辑摘要、删除 |

- 编辑保存不改变 createdAt（排序不变），可选实现 updatedAt 供将来同步，UI 不展示。
- 删除需确认（破坏性操作例外原则）；删除后 toast +「撤销」按钮（5s），撤销是唯一的后悔药。

### 转写与摘要（媒体条目）

媒体条目的文字层，**v1 手动编辑；Phase 3 起由 AI 自动生成**，用户始终可改：

- **转写（仅录音）**：录音的完整文字面，等价于文本条目的正文——搜索与回顾的根据。
- **摘要（照片 + 录音）**：短文字，时间线的展示面。照片的摘要即图片描述；录音的摘要基于转写压缩而来。

**显示（时间流）**：

- 摘要渲染在媒体下方，文本条目同款样式（次要色）；无摘要不占位、无「添加摘要」引导（保持流干净）。
- 录音无摘要但有转写 → 摘要位兜底显示转写首行（截断）。
- 转写全文不进时间流（可能很长），只在编辑弹层中查看。
- Phase 3 生成中 → 摘要位显示流水线状态「转写中…」→「摘要生成中…」，完成原地替换；失败 → 「生成失败 · 重试」，点按重试。

**编辑**：

- 入口：长按 / 右键菜单「编辑转写」「编辑摘要」；摘要位显示的文本点按即编辑——显示的是什么就编辑什么（摘要，或兜底的转写）。
- 形态：底部弹层 textarea +「保存」，保存即生效无确认；清空保存 = 删除该字段。
- 文本条目无此二者，其编辑入口就是正文编辑。

**生命周期（AI 到来后）**：

- 录音保存 → 异步生成转写 → 基于转写生成摘要；照片保存 → 异步生成描述。均不阻塞录入主路径，失败可重试。
- **用户编辑过的字段视为定稿**：自动生成 / 重新生成不覆盖；想换 → 编辑弹层内「重新生成」按钮显式触发。
- 手改转写后摘要不自动跟着重算（它也是定稿）——要更新，显式「重新生成」。
- 可搜索文本：正文 / 照片摘要 / 录音转写 + 摘要（§7）；人工改这些字段 = 人工优化该条目的可搜索性。

## 9. 关键决策与理由

| 决策 | 备选 | 理由 |
|---|---|---|
| 最新在最底部（聊天式） | 列表倒序（最新在上） | 录入后条目出现在输入栏正上方，因果就近；「看最新」= 打开即底 |
| 录音点按切换，非长按对讲 | 微信式按住说话 | 长按易误释放，容错差；点按两步代价相同 |
| 保存路径零确认（含拍照无预览） | 快门前预览确认 | 确认是对每条记录收税；删错的代价（长按→删除→撤销）远低于每条多一步 |
| 不自动弹键盘（窄屏） | 打开即聚焦 | 打开动机一半是查看；且想打字时点框与聚焦的成本相同 |
| 条目无标题 | 首行转标题 | 省一步思考「起什么名」；首行天然承担标题视觉职能 |
| 搜索限定当前笔记本 | 全局跨笔记本搜索 | 笔记本即上下文边界，搜索是「在这本里找」；跨库检索等真实需求出现再加 |
| 摘要可编辑（AI 生成 + 人工可改） | 摘要只读 | 人工校对是生成质量的安全网；摘要即媒体的搜索文本，可编辑让搜索可被人工优化 |
| 录音双层文本：转写全文 + 摘要 | 单层（只有摘要或只有转写） | 转写是「内容」（可搜索的全文），摘要是「展示」（时间线锚点）；两个职责都需要 |
| 媒体与文字严格分离 | 发图配文案 | 「一条一档」原则；组合记录后置 |

## 10. 空状态与边界情况

- **首次启动**：只有 default，时间流为空 → 流中央提示「⬇ 在下面记第一条，或点 🎤 / 📷」。
- **新建笔记本后**：切到空流，提示同上（去掉 default 相关文案）。
- **搜索无结果**：「没有匹配“关键词”」。
- **录音被系统打断**（来电/其他应用抢麦克风）：已录部分自动保存，不打断即无感知。
- **拍照/录音权限被拒**：入口按钮按下时引导去系统设置开权限，不让用户进到一半失败。
- **媒体文件损坏/缺失**：缩略图占位「图片已丢失」，不 crash；条目仍可删除。
- **同分钟多条**：时间戳可重复，排序稳定（按 id 插入序）。

## 11. 验收：操作步数表

| 场景 | 步数（不含打字/说话/取景本身） |
|---|---|
| 记一段文字（窄屏） | 2（点框、➤）；宽屏 1（Enter 发送） |
| 录一段音 | 2 |
| 拍一张照 | 2 |
| 相册导入一张 | 2–3 |
| 搜索定位一条文本 | 1（进入搜索）+ 输入即过滤 |
| 查看/补录转写或摘要（媒体，v1 手动） | 2 + 输入（长按 → 菜单项） |
| 切换笔记本 | 窄屏 2 / 宽屏 1 |
| 新建并切到新笔记本 | 3 |
| 删除一条记录 | 长按 → 删除 → 确认 = 3（含唯一必要的确认） |

任何新功能合入前先回答：这张表会变长吗？

## 13. 对现有代码的影响（实现时参考）

- `Note(title, content)` → `Entry(type, …)`；`NoteStore` 拆为 `NotebookStore`（笔记本列表 + 当前笔记本）与 `EntryStore`（条目流），仍为 ChangeNotifier，JSON 持久化骨架可复用。
- 三 Tab 导航壳（NavigationRail/NavigationBar）→ 侧栏（笔记本）+ 时间流 + 输入栏。
- 保留可复用：主题设置与持久化、LIKE 匹配逻辑（范围收窄到当前笔记本）、`ListenableBuilder` 模式。
- 新增依赖预期：`record`（录音）、`camera` 或系统相机 intent、`image_picker`（相册）、`audioplayers`（播放）。均为本地能力，符合零外部依赖原则。
